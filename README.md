# Voxy LOD Generator

Voxy LOD Generator 是一个面向 Minecraft 1.21.1 NeoForge 的 LOD 批量生成模组，配合 Roxy 和 Voxy 使用，并兼容 C2ME。它可以按指定的生成原点、圆形区块半径和线程数生成并保存 LOD，通过有界任务窗口、及时释放临时数据及队列限流，降低长时间生成时内存不断增长的风险。

模组支持暂停、停止和断点续跑，还能在 F3 页面实时查看生成进度、速度、预计剩余时间、队列和堆内存，适合需要提前构建超远视距地形的单人游戏及内嵌服务端。

经测试，在X7 358H+32G笔记本平台上，分配10G内存，新蒸程整合包，连续生成区块2小时无掉速，无内存溢出。

## 功能特性

- 自定义生成原点、圆形区块半径和后台转换线程数。
- 按需加载或生成区块，并直接写入 Voxy 的 LOD 数据库。
- 使用有界任务窗口，不预先保存整个生成范围的坐标列表。
- 对 Voxy 保存、渲染队列和 C2ME 存储读写积压进行限流。
- 支持暂停、继续、停止、断点续跑、重新生成和从指定索引起始。
- F3 实时显示任务状态、进度、速度、队列和内存。
- 每个维度、原点和半径组合使用独立断点文件，每连续完成 1000 个区块保存一次；不保存庞大的已完成区块集合。

## 运行环境

| 组件 | 要求 |
| --- | --- |
| Minecraft | 1.21.1 |
| NeoForge | 21.1.241 或更高版本；已验证 21.1.241 |
| Roxy | 0.4.0 或更高版本；已验证 0.4.2 |

| C2ME | 可选；已验证 0.4.0-alpha.0.124+1.21.1 |

使用 C2ME 时，请保持其区块存储与读写优化启用。C2ME 的兼容性验证针对上表版本；其他版本的内部接口可能不同。

## 安装

1. 安装匹配版本的 NeoForge、Roxy 和 Voxy；需要时安装 C2ME。
2. 将 `voxy-lod-generator-1.1.0.jar` 放入客户端的 `mods` 目录。
3. 启动游戏并进入单人世界，等待 Voxy 渲染器初始化完成。
4. 使用 `/voxylod` 命令开始生成。

命令需要权限等级 2；单人游戏通常需要开启作弊。建议在正式存档中先进行小范围测试。

## 快速开始

以方块坐标 `[0, 0]` 为原点，生成半径 4096 区块的圆形范围，并使用 4 个 LOD 转换线程：

```text
/voxylod start 0 0 4096 4
```

4096 区块半径约等于 65,536 方块，圆形范围内共有 **52,706,921 个区块**。该任务需要很长时间和大量磁盘空间，请务必提前备份存档并预留足够空间。

生成过程中可以使用：

```text
/voxylod status
```

按 F3 查看实时信息。任务完成后会等待 Voxy 保存队列排空，再报告完成。

## 命令说明

| 命令 | 用途 |
| --- | --- |
| `/voxylod start` | 按当前配置启动任务；存在匹配断点时继续生成 |
| `/voxylod start <originX> <originZ> <radiusChunks> [threads]` | 设置原点、半径和可选线程数，然后启动 |
| `/voxylod startFrom <index>` | 忽略当前断点，从当前任务的指定零基索引开始生成 |
| `/voxylod origin <x> <z>` | 设置生成原点，单位为方块坐标 |
| `/voxylod radius <chunks>` | 设置圆形半径，范围为 0～4096 区块 |
| `/voxylod threads <count>` | 设置 1～64 个后台 LOD 转换线程 |
| `/voxylod queue <chunks>` | 设置 1～64 个在途区块的本模组硬上限 |
| `/voxylod pause` | 暂停派发新任务，已在途的区块会继续完成 |
| `/voxylod resume` | 恢复任务派发 |
| `/voxylod stop` | 停止任务并释放资源，保留连续完成断点 |
| `/voxylod status` | 查看进度、失败数、队列和 JVM 堆内存 |
| `/voxylod restart` | 忽略当前范围的断点，从头重新生成 |

一次只能运行一个生成任务。修改原点、半径、线程数或在途上限前，请先执行 `/voxylod stop`，并等待任务完全停止。

`startFrom` 使用圆形游标的**零基索引**，不是百分比。例如任务共有 10000 个区块时，`/voxylod startFrom 5000` 会跳过前 5000 个区块，从索引 5000 开始。索引 0 表示从头开始；索引等于总数表示无需生成。该命令会先保存指定起点到当前任务的断点文件。

### 参数和默认值

- **原点**：使用方块坐标，不是区块坐标；默认 `[0, 0]`。
- **半径**：使用区块，范围为圆形；默认 512 区块。
- **线程数**：默认最多 4 个，处理器较少时会自动降低。
- **在途上限**：默认按线程数计算，至少 16，通常为线程数的四倍，最高 64。已完成但等待连续断点推进的序号使用独立窗口，不占用在途任务额度。

`threads` 控制本模组的 **LOD 转换线程**，不会修改 C2ME 的全局工作线程池。设置线程数时会自动重新计算在途上限；可通过 `/voxylod queue` 单独调整。

## F3 实时信息

打开 F3 后，模组信息会显示在左侧 FPS 信息下方，包括：

- 任务状态、维度、完成数量、百分比、失败数和具体限流原因。
- “完成”和“断点”两种区块/秒速度、预计剩余时间和已运行时间。
- 实际在途区块数、独立断点窗口、转换线程数、Voxy 保存和渲染队列。
- C2ME 读取、存储命令、待写数据、写盘任务和卸载队列，以及 JVM 堆内存、生成原点和半径。

“完成”速度统计已结束生成或转换的任务，适合观察实际管线吞吐；“断点”速度统计连续完成游标的推进，预计剩余时间使用该速度计算。单个慢区块可能使两种速度暂时明显不同。

暂停、停止、等待保存和各类限流都会显示相应状态。任务空闲或完成后仅显示一行摘要。显示数据每 250 ms 更新一次快照；两种速度均每秒采样并进行平滑处理。预计剩余时间是根据近期速度估算的参考值，地形复杂度、C2ME 调度和磁盘性能都可能使其变化。

## 内存控制与断点

为减少大范围任务中的内存增长，模组采用以下措施：

- 环形游标按需计算坐标，不创建全量区块坐标列表。
- 分别限制正在加载或等待转换的重任务，以及已完成但尚未连续提交的轻量序号，避免慢队头任务过度阻塞派发。
- 任务完成时按剩余容量补充派发，每批只执行一次 DistanceManager 更新，不再受每 tick 固定派发配额限制。
- 后台线程使用区块数据快照，不长期保留完整的 `LevelChunk`。
- 完成、取消或停止时释放快照、区块 ticket 和 Voxy 引用。
- 对 Voxy 保存和渲染队列进行背压。
- 通过可选 Mixin 统计 C2ME 尚未完成的异步读取，并分别对待写数据、写盘任务、存储命令和待卸载区块进行限流。
- 断点只保存连续完成游标，不保存已完成区块集合。

各类队列独立判断是否达到**暂停派发的阈值**，不再把相互重叠的 C2ME 生命周期指标直接相加。C2ME 读取、存储命令、待写数据和卸载队列的默认阈值为 64，写盘任务为 128。它们不是 C2ME 内部任务数的绝对硬上限，异步处理可能使显示值暂时超过阈值；限流后应逐步回落。若队列和进度长期没有变化，请暂停任务并检查游戏日志。

### 文件位置

| 内容 | 位置 |
| --- | --- |
| 模组配置 | `config/voxylod.properties` |
| 每个任务的断点 | `<存档>/voxylod/<维度>/x<原点X>_z<原点Z>_r<半径>.properties` |
| Voxy LOD 数据 | `<存档>/voxy/` |

维度、原点和半径共同标识一个任务，每个任务使用独立的断点文件。普通 `start` 只读取与当前配置匹配的断点；旧版 `<维度>.properties` 文件在参数匹配时仍作为兼容回退读取。

每连续完成 1000 个区块会保存一次断点，并保留 15 秒周期的安全保存；启动、停止、服务器关闭和任务完成时也会保存。停止或中断后，少量已派发但未连续提交的区块可能在下次运行时重新处理。

高级用户还可以在配置文件中调整 Voxy 保存和渲染队列阈值。除非明确了解其内存影响，否则不建议调高。

## 常见问题

### 提示 Voxy 尚未初始化或渲染器尚未就绪

先进入世界并确认 Voxy 已启用，等待渲染器创建完成后再启动任务。本模组不提供独立于 Voxy 的存储或渲染实现。

### F3 显示“限流”及具体原因

这表示模组正在等待 Voxy、C2ME、区块卸载或连续断点窗口释放容量，通常是正常的内存保护行为，并不代表任务已经卡死。根据显示的具体原因观察对应队列，以及“完成”和“断点”速度是否随后恢复变化。

### 想重新生成已经完成的范围

使用：

```text
/voxylod restart
```

`restart` 会忽略断点，但不会删除已有 Voxy 数据；生成结果会重新写入 Voxy。

### 是否会在原版世界中生成区块

会。任务可能加载已有区块，也可能实际生成新的原版区块，并向 Voxy 数据库写入 LOD。大范围操作前请备份存档，并确保磁盘空间充足。

## 构建

当前项目的 JDK、Gradle 和依赖缓存均配置在项目目录内。在 Git Bash 中执行：

```bash
bash gradlew-local.sh build
```

构建产物：

```text
build/libs/voxy-lod-generator-1.1.0.jar
```

构建工具链使用项目内 JDK 25，生成的模组类文件面向 Java 21。构建脚本优先使用 `.tools/dependencies/` 中的适配依赖；Voxy 编译依赖需要与 Roxy 适配环境匹配。

开源仓库不应提交 `.tools/`、`.gradle-home/`、`maven-repo/`、`reference/`、`run/`、`build/` 等缓存、下载依赖、参考源码或测试运行文件。
